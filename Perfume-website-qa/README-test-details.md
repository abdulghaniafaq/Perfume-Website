# Perfume X Collections — technical reference (site layout, every test, every rule)

This is the detailed, technical version. For the short plain-language guide, read `README.md` first.

This folder sits **next to** `Perfume-website/` (not inside it), so none of it is ever uploaded to Netlify.
**Upload only the `Perfume-website` folder.**

## Where things live (`Perfume-website/`)

```
Perfume-website/
├── index.html · catalogue.html · how-to-order.html · guarantee.html · faq.html · contact.html · privacy.html · terms.html
├── _headers                  ← Netlify reads this and sends it as the site's security headers (never shown to visitors); see "Security" below.
│                               It must never carry a robots / noindex header: the old "noindex" file was removed on 21 Nov 2026 so search engines may list the site
├── perfumes.html             ← every perfume A to Z, grouped by house, each name a link to its own page
├── perfume-<slug>.html (627) ← one page per perfume: sizes and prices, when to wear it, notes (only where verified), questions, similar perfumes.
│                               GENERATED from data/products-data.js by seo-build/ (do not edit by hand; see "Perfume pages" below)
├── guides.html · guide-*.html ← the Guides (generated by guides-build/)
├── llms.txt                  ← a plain-text summary for AI assistants
├── robots.txt · sitemap.xml  ← for search engines; they name the address perfume-x-collections.netlify.app (change it in these two files, in the
│                               canonical / og:url / og:image lines at the top of every page, and in the structured data in index.html, if the address changes)
├── data/                     ← the two files you edit
│   ├── site-config.js        brand, WhatsApp number, currency, style groups, guarantee multiple
│   └── products-data.js      the 627 fragrances (replace when prices change)
└── assets/
    ├── images/                   ← one 800px picture per product (<slug>.jpg) + a 240px copy in thumbs/ for the cards and the cart; og-image.jpg = the 1200×630 picture shown when a link to the site is shared, apple-touch-icon.png = the phone home-screen icon; brands/ = the 30 logos on the homepage; minis/ = the 32 mini pictures (800px + thumbs/)
    ├── css/
    │   ├── site.css          shared by every page: colours (:root), header, buttons, sections, footer, cart, responsive rules
    │   ├── catalogue.css     catalogue page only: filters, product cards, pager, quiz, photo viewer
    │   ├── product.css       perfume pages only
    │   └── contact.css       contact page only: request form
    └── js/
        ├── common.js         every page: menu, cart, WhatsApp links, helpers (documented at the top of the file)
        ├── quiz.js           "Find my scent" (catalogue page; loads before catalogue.js)
        ├── catalogue.js      filters, search, paging, product cards, photo viewer
        ├── product.js        perfume pages: the Add and Order buttons on each size
        └── contact.js        "Request a perfume" form
```

## Run the tests

```
cd Perfume-website-qa
npm install        # once
npm test           # every test (1,371 on 22 Nov 2026), about 110 minutes; keep the Mac awake: caffeinate -dimsu npm test
```

Run one file while you work: `node --test responsive.test.mjs`, or one test by name:
`node --test --test-name-pattern="full request" contact.test.mjs`.

Needs Node 20+ and Google Chrome. The cross-browser file also uses Playwright's WebKit (the Safari engine) and Firefox: `npx playwright-core install webkit firefox` once (Firefox may be refused by a sandboxed environment, in which case its tests are reported as skipped). If Chrome isn't in the usual macOS place:
`CHROME_PATH="/path/to/chrome" npm test`. To test a different copy of the site:
`SITE_DIR="/path/to/site" npm test`.

Re-run after changing anything in `data/`, `assets/` or the `.html` files.

## Perfume pages (627)

The pages are **generated**, never hand-edited: `node seo-build/build-all.mjs` (run it from this folder) rewrites the guides, `perfumes.html`, all
627 `perfume-<slug>.html`, the structured data and footer links on the other pages, and `sitemap.xml` in one go. Run it, then `npm test`,
**whenever `data/products-data.js` changes** (a price, a new perfume, a new photo); `products.test.mjs` fails if a page no longer matches the data.

What a page says comes only from the data: house, name, scent family and gender (all 627 are now tagged: the 393 missing scent families and 427 missing genders were added on 22 Nov 2026 from the owner's research workbooks), strength read from the name (EDT, EDP, Parfum...),
every size with its exact price, per-ml price and tester saving, and, derived from them, where the price sits in the house and in the style.
**Season and time-of-day advice follows only the scent family and strength, and the page says so; where neither is known the page says that instead of guessing.**
Notes are published only for the 20 perfumes whose independent sources fully agreed (`seo-build/details/notes.json` also holds 16 more with `"confidence": "medium"`, which are held back).
To publish more, add sourced entries there (two agreeing sources each) and rebuild.

## Security (Netlify)

`Perfume-website/_headers` is read by Netlify and sent with every file: HTTPS for a year (HSTS), a strict **Content-Security-Policy** (this site's own scripts, styles and
pictures; Google Fonts only for the fonts; one inline script, the light/dark switch, allowed by its fingerprint; nothing may frame the site; no plug-ins), no content sniffing,
no framing, short referrers, camera / microphone / location / payment / USB / sensors switched off, and a window opened by another site cannot reach back.
`security.test.mjs` loads every page under exactly these rules, so a page that would break on Netlify fails here first (it already caught inline styles in three guides).

Things to know when you change the site:
- **Adding any outside service** (analytics, a chat widget, a map, other fonts) needs its address added to the policy in `_headers`; the browser silently refuses it until then, and the tests fail to tell you.
- **Editing the small inline script** in the page head changes its fingerprint; `security.test.mjs` prints the new one to paste into `_headers` (and the pages are all generated, so change it in `seo-build/shared.mjs` and the eight hand-written pages).
- Never add a `noindex` / `X-Robots-Tag` line: it would hide the site from Google and AI search (the launch checks fail if it appears).

What no test can do, and only you can: switch on **two-factor sign-in** for your Netlify account (and the Google account behind Search Console), keep "Force HTTPS" on, and never share the Netlify
deploy or API tokens. Once a **custom domain** is chosen, consider adding `includeSubDomains; preload` to the HSTS line (a one-way step, so decide it then) and a `/.well-known/security.txt` with the contact you want researchers to use.

## Photos

The pairing of picture to product comes from your own `_Image_Index.xlsx` (brand + fragrance → image file), not from guesswork:
all 627 products have a photo. `photo-mapping.csv` lists every product with the file you named for it, the original photo number
and the file the site uses. Pictures are trimmed of white margin, squared on white, and saved at 800px (viewer) and 240px (card).
Two pictures are used exactly as your index says but don't look like the product (Versace Eros EDT is a hand holding a gift box;
Afnan Turathi Pour Homme shows a box reading "Supremacy Collector's Edition") — worth replacing when you have better photos.

To change a photo on purpose: replace both files for that slug, then `node lib/make-photo-manifest.mjs` to re-fingerprint the set.
`photos.test.mjs` fails if a picture changes without that step, which is what stops two products being swapped by accident.

## How the checks work

`lib/oracle.mjs` and `lib/quiz-oracle.mjs` are independent re-statements of what the filters and the quiz
*should* do, computed straight from `data/products-data.js`. Each scenario drives the real page (clicks,
dropdown changes, typing), reads everything a visitor can see, and compares it with the oracle. A failure
message lists the exact combination and what differed. `lib/responsive.mjs` holds the device list and the
layout audit.

WhatsApp links are never really opened: the test harness replaces `window.open` and records the URL.

## Rules the tests lock in

- **Price bands** don't overlap: `lo <= price < hi` (₹1,000 is in "₹1,000 – ₹3,000" only). Five bands, up to ₹10,000+.
- **Catalogue controls**: a search box with one **Filters** button, four style tabs (All / Designer / Luxury & niche /
  Middle Eastern) and a sort pill. The Filters panel holds House (a dropdown) and For, Scent, Price and Size (tap to choose,
  tap again to clear). The sort offers only *Price: low to high* (the starting order) and *Price: high to low*. There is no
  "Inspired by" filter and no "House A–Z" sort; the search box still finds fragrances by the scent they're inspired by.
  Products with the same price keep catalogue order (house, then name).
- **Light / dark mode**: the page follows the device's setting until the visitor taps the sun/moon button; that choice is
  remembered. Every colour is a named variable in `site.css` (gold *text* is darker in light mode; gold *fills* under
  dark text stay bright in both), so a theme is just a different set of values.
- **Live filter counts** (the catalogue page; checked by selecting each option for real): the number beside each dropdown option is how many fragrances you'd get by choosing
  it with the other filters as they are now; options that would give none are greyed out (your current
  choice always stays selectable). When nothing matches, the page lists which filters to remove to get results back.
- **Search** (catalogue page): by **house name and perfume name** — not the "inspired by" text, not the size or packaging (those have
  their own filters). Every typed word must appear in the house + name, in any order ("lattafa" finds a whole house, "tom ford oud"
  Tom Ford's oud perfumes, "khamrah" the perfume); case, accents and apostrophes (straight or curly) are ignored. While typing, up to
  eight suggestions are offered: up to two **houses** first (with how many fragrances each has under the current filters), then
  matching **perfumes** (best first: name starts with what was typed, then a word of the name, then the house, then every word
  starts a word, then anywhere; shorter names first). Choosing a house searches for the house; choosing a perfume searches for its
  house + name. The list follows the other filters, picked-out letters are highlighted, and it works by mouse, touch and keyboard
  (↑ ↓ Enter; the first Esc puts the list away, a second clears the box). The contact form's "Already in our catalogue?" box
  matches house, name and "inspired by" text; its links to the catalogue carry "House Name".
- **Homepage**: the hero shows three real photos (Chanel Bleu De Chanel EDP, Tom Ford Black Orchid Parfum, Hermes Elixir Des
  Merveilles EDP), each linking to that perfume. "Houses we carry" is three scrolling rows (Middle Eastern, Designer, Luxury &
  niche) of the 10 houses with the most fragrances in each style, worked out from the product list, each shown by its **logo** (trimmed
  and sized so thin wordmarks and chunky emblems weigh about the same, on a white tile because the logos are drawn on white);
  the rows pause on hover or with the Pause button, and are a still list for visitors who ask their device for less motion.
  The logos are `assets/images/brands/<house>.jpg`; after changing one on purpose run `node lib/make-logo-manifest.mjs`.
- **Mini pictures**: a mini (spray, dab or vial) can have its own picture, listed in `miniPhotos` in `site-config.js` (files in
  `assets/images/minis/`, named `<slug>--<form>.jpg`, plus a 240px copy in `thumbs/`). The card's picture **follows the selected
  size from the very first moment**: if the pre-selected size is a mini with its own picture, the card opens on it (and a card that
  only sells a mini shows it straight away); tapping another size shows that size's picture (its own mini picture, or the normal
  photo) and tapping back restores it. Enlarging the photo shows the picture for the selected size. A missing mini file falls back
  to the normal photo. The quiz results ("Take a scent quiz" → top picks) show pictures by the same rule, for the size each result is listed at. The cart shows the same picture as the card for the size in the cart (a mini's own picture when it has one, else the perfume's photo). The homepage keeps the normal photos. `mini-photo-mapping.csv` records, for each of the 51 supplied
  images, whether it was used and why not if not. After changing pictures on purpose run `node lib/make-mini-manifest.mjs`.
- **FAQ boxes**: closed by default; opening one closes whichever other box was open (all FAQ boxes on the site, via the `.faq` group).
- **Legal pages**: `privacy.html` and `terms.html`, linked from every footer. Terms: the order journey (WhatsApp request → availability →
  payment on WhatsApp with a screenshot → we confirm receipt → packing within 48 hours → shipped generally within 3–4 days depending on
  state → courier updates on the customer's number), payment only on WhatsApp, the mini-vial option for customers who want to try first.
  Plain-language templates — worth a read by whoever advises you on legal matters, especially cancellation/returns, which they don't cover.
- **Homepage numbers**: the hero button reads "Explore All Fragrances" and the three style cards show no counts.
- **Cart**: every item shows the same picture the catalogue card shows for that size — a mini's own picture where it has one
  (32 of them), otherwise the perfume's photo (the same small file the cards use; a missing mini file falls back to the photo, and the
  bottle outline stays if there is no photo or the file is missing). The note says "The photo shows the mini you will receive" when the
  picture is the mini itself. A small **i** beside every mini (spray, dab, vial, roller ball, kit) and every tester shows
  "What you'll get" — what will actually arrive, since the catalogue has one full-size photo per perfume. It opens by itself while
  the mouse is over the **i** (or it has keyboard focus); a click keeps it open, a second click closes it; on a touch screen a tap
  opens it and a second tap closes it. Normal bottles and gift sets have no icon. The note is never part of the WhatsApp order message.
- **Quiz — the numbers always add up.** Each question sorts every fragrance still in the running into
  exactly one of its options, so the options add up to the number in the running; picking one keeps exactly
  those, and the next question adds up to that. Fragrances that fit none of a question's options sit in a
  catch-all row ("Not specified" for gender or scent family: shown only while some perfume lacks that tag, which today none does, so the row and its explanatory sentence are hidden; six
  ungrouped houses → "Other houses"; houses beyond the top eight → "Other classics"). The loved-scent
  question only appears after "inspired by a famous scent". A fragrance has several sizes but is counted
  once, at its cheapest listing, which decides its price band and size group and is the one shown. Results
  are listed cheapest first (pricier first for budgets from ₹6,000). A question is skipped when fewer than
  two options have anything in them, and empty options are hidden, so nobody reaches an empty result.
- **Phone number**: shown masked (`+91 ••••• ••272`) or hidden (`numberDisplay` in `site-config.js`);
  the digits are never written into any page — only into the link built at the moment of a tap.
- **Request form**: only the filled-in fields appear in the message; nothing the visitor types is ever
  run as code.
- **Responsive**: the header menu collapses at 1000px and below; tap targets are at least 44px (chips 40px); form
  text is 16px+ on phones so iPhones don't zoom; no text under 11px (volume labels 9px); big screens get a
  wider page and slightly larger type.
